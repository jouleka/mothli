# Handoff, 18 November 2026

This is written to be given to a new AI session as its first message. It is complete on its own:
read it, then the files it names, before doing anything.

---

You are taking over **Mothli**, a reading app with an AI companion that knows a book only as far as
its reader has read it. The repository is `jouleka/mothli` on GitHub (FastAPI under `backend/app`,
React and TypeScript under `frontend/src`). The owner is one person, building it into a product for
real readers. `main` is at `a38c040`. Nothing has been deployed yet.

## The owner's rules (his words where quoted; none are negotiable)

- "Spoiler safety is not negotiable: for every book, nothing beyond that book's read position,
  including in cross-book answers. For unread books use only a spoiler-free blurb; if any proposal
  weakens this, say so and offer an alternative."
- "Every shown sentence stays checked as in stream_conversation.py."
- "Use the ChatGPT subscription (llm_transport="codex-local"), not the OpenAI API. State expected
  spend before any paid run. Jev runs through TypeSafe." Never ask him for an API key to measure
  cost: measure tokens on the subscription and multiply by the public price list
  (`backend/app/cost/limits.py`). The subscription's command-line tool adds about 7,780 input tokens
  to every call; subtract them before pricing.
- Jev (the checker, paid per call): at most **$0.25 a day** on tests, every paid run with a hard
  stop, and say the expected spend before you start.
- "Prefer removing work to adding it." No AI co-author or "generated with" line on any commit or
  pull request, whatever a tool suggests.
- `main` takes changes only through a pull request; you open it, wait for GitHub's checks, and
  merge it yourself (`gh pr merge --merge`). Run `ruff check app tests scripts` before reporting.
- Run the work yourself in a loop: give each step to an agent (Opus, medium effort, in its own git
  worktree; never a more expensive model), review what comes back (read the diff, rerun the tests,
  use the thing), merge if it holds, go on. Ask him only for real judgment calls.
- Voice: Mothli is a playful, helpful friend, "very natural", never "I ask a question, I get an
  answer, or robotic". English only for now.
- "The user experience has to be excellent." The reader is someone who "knows nothing how AI works".
- Explain things to him plainly. He stopped a proposal once because "shared" was not explained; his
  test for anything shared between readers is: "Shouldn't Mothli mostly know only about the current
  user and what they've read?" Say so plainly whenever an idea removes a layer of spoiler protection.
- Never open, print or copy `.env`, keys or tokens. Never touch his other Docker containers
  (`buzzfetti-*`, `torotoro-*`).

## What exists (all merged)

Two modes share one set of rules. **Local mode**: one reader, SQLite, his own machine; it is where
every spoiler rule was first built and where real models can be tried (the subscription works only
there). **Hosted mode**: many readers, PostgreSQL 16 with row-level security, sign-in through an
outside OpenID Connect service, book files encrypted in object storage, a worker for background
jobs, the owner paying for the AI under caps. Hosted mode runs the *same unchanged modules* over
its own storage adapters; parity tests compare the two at every reading position.

Hosted mode now has: the read map and place sync; the chat in a book and the home chat, every
sentence checked; chapter notes and Mothli's memory of the reader as background jobs; caps that
count real spend, where a reply under way always finishes; sign-in, account sheet, account deletion
(kept 30 days, then erased by a daily job), "take a copy of my data"; the free library with
one-click add; removing a book (which erases what was about it); and the story memory (cast,
person cards, story so far): built chapter by chapter by jobs, and for free-library books built
once by the operator and handed to each reader **only up to their own place** by one database
function. Deployment files exist for his server behind a Cloudflare tunnel.

Read, in this order: `docs/adr/0041-companion-in-hosted-mode.md` and
`docs/adr/0042-story-memory-in-hosted-mode.md` (the two design records, each with "Built on…" lines
saying what the code really does), `docs/product/companion-open-items.md` (the checklist: about 235
open items, every step updates it), `docs/runbooks/hosted-deployment.md`,
`docs/product/go-live-map-2026-11-17.md`.

## Decisions he has made

- He pays for the AI. Caps to start: $0.10 a reader a day, $2.00 a month, $5.00 a day for everyone.
- Sign-in through an outside service (which company: not chosen). Hosting: his own server behind
  Cloudflare. English only.
- A deleted account is kept 30 days, then erased. A reader may come back and keep it.
- Story memory is built before launch, not after. Free-library books: built once, handed out only
  up to each reader's place, no later data handed out for any reason. A reader's own uploaded book:
  the code exists and is **switched off** (`HOSTED_READER_STORY_MEMORY`); he has not decided to pay
  for it.

## What was measured

- Story memory costs about **$7.30 for one novel** on `gpt-6.1-terra` (about 9 cents a chapter,
  53,000 tokens in and 6,800 out per chapter, no Jev). The cheaper model failed the review at
  chapter 2. A chat reply costs about 1 to 2 cents plus a tenth of a cent of Jev; chapter notes about
  a cent a chapter. None of this has been measured on a paid account (discounts for repeated text,
  speed).
- One real-model run of the "later name" probe (does the writer's own memory of a famous book leak
  a later character, now that the cast list cannot block names it was never handed?): eight
  questions at chapter 3 of Pride and Prejudice, 18 sentences shown, none leaked. One book, one run.

## What he asked for last, and has not been done

**1. Make it one product.** His words: "now that we're moving to hosted, shouldn't we delete or
remove things that we don't need anymore? … delete or remove everything that made it just a solo
product for me, for example, for testing purposes. Aside from things we, of course, need still,
like the ChatGPT subscription." Nothing has been removed yet, on purpose. What I found:

- Local mode cannot simply be deleted. Hosted story memory builds each chapter in an in-memory
  SQLite copy (`backend/app/hosted/companion/story_memory.py`); about 124 of the 172 test files
  exercise the shared spoiler rules through the local stack; the parity tests need it as the
  reference; and the ChatGPT subscription, which he wants kept, runs only in local mode
  (`backend/app/config.py` refuses `codex-local` elsewhere).
- So the honest shape is: local mode stops being a product and stays as the development and test
  harness. What can go is what only a solo user needed and nothing above depends on. Candidates I
  have seen, each to be checked, not assumed: the reader's-own-AI-key path in hosted mode
  (`HOSTED_READER_KEYS`, the credentials tables and routes, `ProviderSettings.tsx`, the retired
  `ingest_book` reader-key jobs); the local-archive migration into hosted
  (`backend/app/hosted/local_migration.py`); older reply paths the streamed chat replaced (the
  non-streamed `/ask`, the answer cache, prepared questions, recap pre-warming) and their settings;
  local-only screens such as the AI status and connection settings; one-off audit scripts under
  `backend/scripts`; `spikes/`.
- Do it as its own design record first (an ADR 0043): list every local-only or solo-only piece,
  mark each keep-as-harness or remove, with the reason and what depends on it; get his yes; then
  remove in small pull requests, each with the suites green and **no spoiler test weakened or
  deleted without an equal one in its place**. Removing tables means migrations; the account
  erasure, book removal and data export tests find tables from the database's own catalogue and
  will tell you what you missed.

**2. The rest before a first deployment**, in the order I would take them:

- Terms and privacy pages. They must name the model provider and TypeSafe, say that an erased
  account stays in backups until those expire, and say that notes on free-library books are
  prepared once for everyone. Offer him a draft.
- Monitoring and alerts (worker not claiming, a provider pause, spend near the day cap, a story
  memory job stopped after three chapters it could not do).
- Which free-library titles to build, and with what: about $7 each. Hosted mode cannot use the
  subscription, so building them needs a paid model account, or a decision to build editions in
  local mode on the subscription and load them (not designed; check the subscription's terms
  before proposing it).
- Repeat the later-name probe on two more famous books and later places (about half a cent each).
- "Explain / Define" on a picked passage: hidden in hosted mode; needs moving onto the platform's
  models.
- Reading-history import (the second half of ADR 0041's part 11).
- A walk of hosted mode with real models, and offline reading: not done.
- The deployment itself: needs from him a domain, a Cloudflare tunnel token, the sign-in service
  and its three settings, a model account, and where off-server backups go. Cloudflare's free plan
  refuses uploads over 100 MB and Mothli allows 128 MB.
- Then three to five real readers before anyone else.

**3. Known weak spots worth fixing early** (all in the open items): several tests order jobs by
`created_at` and fail when the clock steps back; every adapter call opens its own database
connection (unmeasured under load); notes share the daily allowance with the chat; six Dependabot
pull requests are open and untouched (#7, #20, #22, #72, #73, #74); a dependency-audit exception
for `picomatch` is in `.github/scripts/npm-audit.mjs` and should go when a fixed version exists.
